# 配对指南

配对让两台设备互相认识并交换公钥，是使用一切远程功能的前提。**每对设备
只需配对一次**，之后连接、重连都不再需要配对码。

## 配对码的规则

配对码是 6 位数字，由 crypto/rand 生成，遵循以下生命周期：

- **5 分钟有效**，超时自动作废；
- **单次使用**：一次成功配对即失效；
- **同一时刻只有一个邀请**：生成新配对码会作废旧码；
- **内存态**：rtd 重启后未使用的配对码即消失；
- **错 5 次立即作废**：防爆破；即使未错满 5 次，猜码方还会被按设备
  指数退避（第 1 次错后 2s 起步，翻倍递增，封顶 5 分钟）。

安全机制：配对码本身**不离开设备**——它作为 SPAKE2（P-256）口令参与密钥
协商，网络上看不到码；协商结果与 TLS 通道绑定，经中继配对也无法被
中间人替换。无论成功与否，对端看到的失败信息统一是 `pairing failed`，
具体原因只写进本机 `rtd.log`（防存在性探测与信息泄露）。

## 两种配对路径

### 同一局域网：直连配对

1. A 设备生成配对码（Web UI 首页「生成配对码」或 `rt pair`）；
2. B 设备输入 **A 的地址 + 配对码**（Web UI「连接其他设备」或
   `rt pair 192.168.1.20:27183 482913`）。

A 的地址怎么看：A 的 Web UI 首页「局域网发现」卡片，或 A 上跑
`rt status`（`listen :27183`），地址即 `A的IP:27183`。

局域网发现（mDNS）在多数场景能自动列出附近设备，点击即可带上地址。
**mDNS 不可靠时（Android 常见、跨网段必现）发现列表为空不是故障**，
手动输入 IP 即可。

### 跨公网：经 hub 配对

两台设备先都配好同一个 hub（见 [hub 部署指南](hub-deployment.md)），
然后流程完全相同：A 生成配对码，B 用 `A的公网地址:27183`（或 hub 下发
的对端地址）+ 配对码发起。配对流量走中继时，SPAKE2 协商在中继两端
端到端进行，中继只见到密文。

配对成功后，两台设备各自在 `peers.json` 记下对方公钥与最后地址；之后
连接优先直连（含对方最后已知地址），失败自动经 hub 中继。

## 配对之后

- 新配对设备**默认全功能开放**（终端/文件/转发都允许，文件访问限本用户
  主目录，转发拨号限回环）。建议立即在 Web UI 设备详情页「权限」里按需
  收紧——语义见 [安全说明](security.md#按设备权限)。
- **重新配对（re-pair）**：一方删除配对后，双方需要时可在已配对连接上
  直接重新走配对流程（无需先断开）；identity.key 删除重建后，旧配对
  全部失效，需与新设备重新配对。
- **解除配对**：Web UI 设备详情页「删除配对」。对方设备上仍会保留单向
  记录（对方也删一次即可），删除后对方再连入会被当作未配对设备拒绝。

## 常见失败

| 现象 | 原因与处理 |
|---|---|
| 一直 `pairing failed` | 对方码错/过期/已被 5 次错误作废；也可能你在退避窗口内（刚错过多码），等几分钟再试。真实原因看**本机** `rtd.log` |
| 配对码输入对了仍失败 | 码可能已被新码顶替（同一设备同时只有一个邀请）；重新生成 |
| 经 hub 配对失败 | 两端 hub 配置不一致、hub 不在线；先确认设备已连上 hub（`rtd.log` 出现 `hub connected`） |
| 直连超时但 hub 可用 | UDP 27183 被防火墙/NAT 阻断；先用 hub 路径完成配对，直连问题见[故障排查](troubleshooting.md) |
