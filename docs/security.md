# 安全说明

本文面向使用者，解释 remotetool 的安全模型：什么被保护、靠什么保护、
边界在哪。协议与实现细节见 [design.md](design.md)。

## 威胁模型

remotetool 的能力是高权限的（执行命令、读写文件、开隧道），设计目标是：
**只有你配对过的设备能使用这些能力，且中间网络（含自建中继）看不到任何
明文**。不设防的场景：本机已被攻破（攻击者同权限用户可读 identity.key、
config 与内存）、rtd 所在主机的其他管理员用户。

## 身份与配对

- 每台设备首次启动生成 **Ed25519 密钥对**（`identity.key`，0600，hex
  seed）。设备 ID 是公钥指纹（SHA-256 前 8 字节的 16 位 hex）。
- **配对码**（6 位、5 分钟有效、单次使用）作为 **SPAKE2-P256** 的口令
  参与密钥协商：码本身不上网络，协商出的密钥与 TLS 通道绑定
  （"rtd/cb/v1"），经中继也无法被中间人替换。
- **防爆破**：错码 5 次邀请即作废；按来源设备指数退避（2s → 5min）；
  未配对连接有并发信号量 + 令牌桶限流。对端只见统一 `pairing failed`，
  具体原因只写本机日志（防存在性探测）。
- 连接认证：QUIC/TLS 1.3 双向证书，只接受自签 Ed25519；已配对设备按
  钉扎公钥校验（有意不查证书有效期/CA——自签体系下 CA 无意义）。
  删除 `identity.key` 即重置设备身份，旧配对全部失效。

## 传输加密

- 设备间直连：QUIC + TLS 1.3，控制流（JSON RPC）与数据流（终端/文件/
  转发）都在同一加密连接内。
- 经 hub 中继时：中继流内部再协商一层**端到端 TLS**（两端设备证书、钉扎
  校验不变）。因此 **hub 只见设备 ID 和密文**，看不到命令、文件内容与
  转发流量——把 hub 放在不可信 VPS 上是设计内场景。

## Web UI 认证

Web UI 只监听 `127.0.0.1`（其他网卡根本不 bind），不在网络层暴露：

- 首次访问用带 token 的 URL（`rt url` 可重取）；校验通过后种
  `rt_token` cookie（HttpOnly、SameSite=Strict、30 天），token 不留在
  地址栏。
- 所有 API 都要求 token（header / cookie），失败统一 401。
- **CSRF**：cookie 认证的写请求校验 Origin，非同源 403；WebSocket 握手
  校验来源端口。
- 请求体 1MB 上限、请求头超时与大小限制、静态文件显式白名单。
- **请勿**将 Web UI 端口反代到公网——它只打算给本机/SSH 隧道用。

## 按设备权限

配对只解决"是谁"，每台设备的能力可在 Web UI 设备详情页「权限」页
单独收窄（改动即时生效于已建立的连接）：

| 开关 | 缺省 | 说明 |
|---|---|---|
| 终端 / 文件 / 转发 | 允许 | 关闭后该设备对应功能请求被拒，与"目标不存在"返回同一话术 `no such ...` |
| 文件授权目录（file_roots） | 本用户主目录 | 白名单外的路径一律 `path outside allowed roots`（含 symlink 解析后的真实路径校验）。**空列表 = 全部拒绝**，与"未设置（用默认）"语义不同 |
| 转发拨号白名单（FwdAllowHosts） | 仅回环 | mode L 拨号目标必须命中白名单才会放行；缺省时对端只能转发到本机回环 |

新增配对默认全开——建议配对完成后立即按需收紧。转发本身不是开放代理：
任何模式都拒绝以对端为跳板的任意拨号。

## 凭据与日志

- **Web token 不写入日志**：token URL 只打印到 stderr 控制台，rtd.log
  里没有（有自动化测试守护这条）。
- config.json（含 WebToken、hub token）与 identity.key 权限 0600，目录
  0700；文件写入是临时文件+原子替换。
- hub token 保存在本机 config.json；VPS 上的 hub 用强随机 token。

## 已知缺口（当前版本）

- **Web UI 未设 Content-Security-Policy** 响应头（静态资源无构建步骤，
  已列入路线图）；
- **日志无轮转**：rtd.log 追加不清理，长期运行注意磁盘（可手动删除）；
- **无 UDP 打洞**：直连失败即走中继（功能性而非安全性）；
- Android 平台为编译冒烟级，真机行为按 [platform-matrix](platform-matrix.md)
  验收。

## 建议

1. 配对完成后立刻收紧设备权限（尤其长期在线的服务器）。
2. 主机开启磁盘加密：identity.key 与 config.json 明文存放于用户目录。
3. hub 用强 token；不需要 root（监听 27190 >1024）。
4. 不要把 Web UI 端口暴露出本机；远程管理走 SSH 隧道
   （见 [linux-deployment](linux-deployment.md#5-无头服务器的-web-ui-访问)）。
